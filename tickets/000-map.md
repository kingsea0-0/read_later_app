# Hoard Map

## Destination

A spec and implementation plan for "hoard" — a read-later app that lets you one-click save links from anywhere (browser, phone) and browse them in a card-feed reading experience, with AI summarization as a future capability.

## Notes

- **Domain**: consumer read-later / bookmarking tool
- **Tech stack**: Go backend (gin + pgx), Supabase (PostgreSQL + Auth), React SPA frontend, Chrome Extension (MV3), thin iOS native shell (WKWebView + Share Extension)
- **Deployment**: Vercel (frontend), Railway/Fly.io (Go backend), Supabase (database + auth)
- **Auth**: Sign in with Apple + Google OAuth via Supabase Auth
- **Phase 1**: Chrome extension + Web reading experience
- **Phase 2**: iOS app (thin shell + Share Extension)
- **Phase 3**: AI summarization
- **Reading experience**: Card feed, click to original link, no content scraping required
- **Content grouping**: auto tabs by type (All / Videos / Articles) in MVP, user folders later
- **Go backend**: gin framework, domain-layered structure, pgx direct connection to PostgreSQL, JWT validation via golang-jwt, /api/v1/ prefix
- **Chrome Extension**: MV3, action.onClicked (no popup), activeTab permission, chrome.storage.local for tokens, chrome.alarms for token refresh
- **iOS**: WKWebView shell (~100 lines Swift), Share Extension (~80 lines Swift), App Groups + Keychain Sharing for auth
- **Frontend**: Vite + React + TypeScript + Tailwind CSS, React Router v6, React Context for auth

## Decisions so far

- [Supabase 技术方案调研](tickets/001-supabase-research.md) — Free Tier 足够（500MB DB, 50k MAU），推荐 pgx 直连 + supabase-go 双通道策略，OAuth 原生支持，Schema 设计四张表（profiles, bookmarks, tags, bookmark_tags）
- [Chrome Extension MV3 技术方案调研](tickets/002-chrome-extension-research.md) — 使用 action.onClicked 零弹窗方案，activeTab 权限，Web OAuth 传递 session，token 存 chrome.storage.local
- [iOS Share Extension 技术方案调研](tickets/003-ios-share-extension-research.md) — Share Extension 3 文件 ~80 行 Swift，WKWebView 壳 ~100 行，App Groups + Keychain Sharing 共享认证
- [Go 后端 API 设计决策](tickets/004-go-api-design.md) — gin 框架 + 领域分层结构，API 端点 /api/v1/，JWT 验证中间件，pgx 连接池 + Repository 模式 ✅
- [React 前端架构设计决策](tickets/005-react-frontend-architecture.md) — Vite + React + TypeScript + Tailwind CSS，页面路由 /, /auth, /auth/callback ✅
- [Chrome Extension 实现方案决策](tickets/006-chrome-extension-implementation.md) — MV3 纯手写，零弹窗，后台 Service Worker 处理收藏和 token 管理 ✅
- [项目脚手架搭建](tickets/007-project-scaffold.md) — 后端/前端/扩展/迁移全部骨架就绪，Go build + vite build 均通过 ✅

## Not yet specified

- **AI 摘要的具体实现方案** — 调用哪个大模型 API（OpenAI / Claude / 本地模型），如何管理 token 成本，如何做内容抓取（需要引入 readability 等工具），缓存策略。V2 功能，当前不需要深入。
- **用户自定义分组/文件夹** — 是否支持嵌套、拖拽排序、共享等。V2 功能。
- **Safari Extension** — 作为 Chrome 扩展之后的平台扩展，需要调研 Safari Web Extension 的兼容性方案。
- **离线阅读/缓存策略** — 是否需要缓存页面内容供离线阅读，以及缓存策略。
- **搜索功能** — 全文搜索收藏内容的实现方案（Supabase 的全文搜索还是用外部搜索引擎）。
- **部署配置** — 需要配置 Railway/Fly.io 部署、Vercel 部署、Supabase 项目创建。
- **iOS 开发** — Phase 2 需要创建 Xcode 项目、配置 Signing、部署 TestFlight 等。

## Out of scope

- 内容抓取和解析（不做 readability/html 解析，点击跳转原文即可）
- 社交功能（分享、关注、评论等）
- 自有视频/图片存储
- 桌面端原生 app（Mac app 通过 Web 端覆盖即可）
